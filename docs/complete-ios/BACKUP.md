# 备份格式与数据规则

新备份是 ZIP，内部包含 `manifest.json` 及 `media/` 附件。版本标识为 `format: shike`、`version: 2`。兼容旧的 `shike-backup` 版本 1 JSON。

`state` 包含日记、草稿选区和滚动位置、胶囊绝对解锁时间及持久解锁/开启状态、UTF-16 句子引用、完成时元信息、媒体登记、拾影描述及导入时间、卡包、素材使用状态和设置。迁移时保留的原始数据副本不重复放入新备份。

每个附件登记字节长度及 CRC32；解包同时检查 ZIP CRC、路径、版本、日记状态、心情范围和引用关系。最多 20,000 个文件，总解压大小最多 512MB。没有额外的 SHA-256 校验步骤。

恢复分两步：先只读检查并形成合并计划，再经用户确认执行。同 ID 且正文、附件、引用及快照相同则跳过；同 ID 不同内容分配新 ID，并重映射引用来源与目标。正式日记不会被覆盖。已有内容的设备保留本机设置，空库使用备份设置；系统权限不会从备份恢复。

附件先暂存，登记本次导入日志后移动到专用目录，再与数据库事务配合提交。任一步失败只清理本次新文件；重新启动时识别未完成日志并清理。预览期间记录发生变化时须重新生成计划。

拾影累计成功导入数恢复为两端较大的历史值，导入备份不增加这个计数。已使用素材标记取并集；不向恢复的记录重新发放历史彩蛋。

附近迁移传输同一个备份包并复用同一恢复引擎。配对码包含一次性 32 字节随机密钥、会话 ID、局域网 IPv4 地址、端口和十分钟期限。iOS 使用 Network.framework TCP 与系统 TLS-PSK；文件帧使用长度和 CRC32 检查。中断后重新配对发送，不做续传。

参考：[Apple Network 迁移说明](https://developer.apple.com/documentation/technotes/tn3213-moving-from-multipeer-connectivity-to-network-framework)。
